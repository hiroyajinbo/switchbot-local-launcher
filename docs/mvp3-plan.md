# MVP3 計画: 日常運用とPCアプリ化

## 目的

MVP2で完成したローカル操作画面を、ブラウザとターミナルを意識せず日常利用できるPCアプリへ発展させる。
純正SwitchBotアプリが得意なオートメーション作成やシーン編集は重複実装せず、PCから素早く安全に操作する体験へ集中する。

## 基本方針

- ローカルWebアプリを中核として維持し、PCアプリはその起動・終了・表示を管理する薄いシェルとする
- トークンなどの認証情報はブラウザ拡張へ持たせず、ローカル本体だけがSwitchBot APIへ接続する
- 赤外線リモコンの全操作をクイック操作へ並べず、専用リモコン画面から必要な操作だけを割り当てる
- 時刻・曜日・センサー連動などの自動化設定は純正アプリへ任せる
- クイック操作の高度な編集は、リモコン操作の割り当てに必要な範囲へ限定する

## 技術構成

- PCウィンドウは `pywebview` を採用し、WindowsではWebView2 Runtimeを利用する
- 既存のFastAPI/Uvicornは同一プロセス内の管理対象サーバーとして起動する
- ウィンドウを閉じた際はUvicornへ終了通知し、停止完了を待ってプロセスを終了する
- Windowsの名前付きMutexで単一起動を保証し、二重起動時は既存ウィンドウを案内する
- 配布はまずPyInstallerの `onedir` 形式とし、動作と更新手順が安定した後に `onefile` を再評価する
- HTML/CSS/JavaScriptはPyInstallerのデータファイルとしてアプリへ同梱する
- `.env`、`config.json`、ログなどの利用者データは実行ファイルへ同梱せず、
  `%LOCALAPPDATA%\\SwitchBotLocalLauncher` 配下へ保存する
- 開発時は従来の `start.cmd` とブラウザ起動も維持し、PCアプリ固有部分とサーバー本体を分離する

採用理由:

- 既存UIを書き直さず、デスクトップウィンドウとして再利用できる
- pywebviewはWindowsのWebView2 RuntimeとPyInstallerによる配布を公式に案内している
- `onedir` はデータファイルと依存関係を確認しやすく、初期の障害解析と更新が容易
- PyInstallerの `onefile` は同梱データを一時ディレクトリへ展開するため、可変設定の保存先には使わない

## スコープ

### 1. PCアプリとしての日常運用

- アイコンから起動できる
- 二重起動を防止し、起動済みなら既存画面を表示する
- サーバー起動完了後に画面を開く
- アプリから安全に終了でき、バックグラウンドプロセスを残さない
- 起動失敗やポート競合を利用者向けメッセージで表示する
- ログをファイルへローテーション保存し、画面から保存場所を開ける
- Windowsログイン時の自動起動を任意で設定できる
- 日常利用しないデバイスをランチャー上だけ非表示にし、設定を保持したまま復帰できる

### 2. リモコン専用UI

- 赤外線リモコンをデバイス種別ごとに表示する
- エアコンは電源、モード、温度、風量などを1つの操作面へまとめる
- テレビなどは方向、決定、音量、チャンネルなどをリモコン状に配置する
- 操作送信中、成功、失敗を既存デバイスカードと同じ方法で表示する
- APIが提供しない状態値は、実状態と誤解されないよう「最後に送信した設定」として扱う

### 3. クイック操作への割り当て

- リモコン画面上の操作から「クイック操作へ追加」できる
- エアコンは現在選択中のモード・温度・風量を1つの操作として保存できる
- 表示名、グループ、アイコンを追加時に設定できる
- クイック操作の重複やボタン乱立を避けるため、同一内容を検出して上書き確認する
- クイック操作グループを先に登録し、SwitchBotシーンと赤外線クイック操作は登録済みグループから選択する
- グループはデバイスの部屋と同じ導線で追加・並べ替え・削除し、グループ単位で折りたためる
- グループ削除時は所属操作を既定の「シーン」へ移動し、操作を失わない

### 3.1 SwitchBotシーンの同期

- 起動時に未追加のSwitchBotシーンを取得し、クイック操作上部へ件数を表示する
- 未追加シーンは一括追加または編集モードで個別追加できる
- 任意設定で新しいシーンだけを自動追加できる
- クイック操作から削除したSwitchBotシーンは除外一覧へ移し、明示的に解除するまで候補へ戻さない
- 手動登録した赤外線クイック操作とデバイス設定は、この自動追加・除外の対象にしない

### 4. ブラウザ拡張（後半・任意）

- ツールバーのポップアップから登録済みクイック操作を呼び出す
- ローカルPCアプリが停止中の場合は、起動方法を案内する
- SwitchBotトークンや秘密鍵は保持しない
- ローカル本体のAPIだけを利用し、設定と履歴の正本はPCアプリ側へ置く

## MVP3の対象外

- 時刻、曜日、位置情報、センサー値を条件にした独自オートメーション
- 純正アプリと同等のシーン作成・編集機能
- クラウド経由での外出先アクセス
- モバイルアプリの新規開発
- すべての赤外線機器種別への一括対応

## 実装順

1. 現行サーバーの起動・終了・ログ管理を `ManagedServer` として整理する
2. 開発用コマンドからも `ManagedServer` を利用し、ポート競合と正常終了を自動テストする
3. pywebviewによるWindows向けPCアプリシェルを作る
4. 名前付きMutex、既存ウィンドウ案内、ウィンドウ終了時のサーバー停止を検証する
5. `%LOCALAPPDATA%` のデータ領域、初回設定移行、ローテーションログを実装する
6. PyInstaller `onedir` ビルドと起動確認を自動化する
   - GitHub CIのWindowsジョブで、デスクトップビルドとポータブル安全検査を継続実行する
7. SwitchBot APIから取得できる赤外線リモコンとコマンド仕様を調査する
8. エアコンを最初の対象としてリモコンUIを実装する
9. リモコン操作からクイック操作へ割り当てる機能を実装する
10. 必要性を再評価したうえでブラウザ拡張を追加する

## 完了条件

- ターミナル操作なしで起動・終了でき、プロセスが残らない
- 長時間起動してもログが無制限に増えない
- ポート競合などの起動失敗を画面で理解できる
- エアコンの主要操作が専用UIから実行できる
- 任意のリモコン操作をクイック操作へ登録し、再起動後も利用できる
- 既存MVP2の自動テストと主要な手動操作に回帰がない
