# SwitchBot API Capability Notes

Source baseline: SwitchBot Open API v1.1.

## Currently Implemented Locally

- `GET /devices`
  - Used by `python -m app.export_resources`.
  - Returns physical devices and infrared remotes.
- `GET /scenes`
  - Used by `python -m app.export_resources`.
  - Used to generate scene button templates.
- `POST /scenes/{sceneId}/execute`
  - Used by the browser UI.
- `POST /devices/{deviceId}/commands`
  - Implemented but not yet manually verified for each device type.
  - Device ON/OFF button templates can be generated by `python -m app.config_device_commands`.
- `GET /devices/{deviceId}/status`
  - Added for MVP2 investigation.
  - Used by `python -m app.inspect_switchbot`.

## Local Inspection Command

```powershell
.\.venv\Scripts\python.exe -m app.inspect_switchbot
```

Output:

```text
switchbot.inspection.json
```

This file may contain device IDs and home-specific data, so it is ignored by Git.

## Local Inspection Result on 2026-07-10

Summary:

- Devices and infrared remotes: 19 total
- Device status success: 14
- Device status error: 5
- Scenes: 4

Observed status fields:

- Lights: `power`, `brightness`, `color`, `colorTemperature`
- Contact Sensor: `battery`, `moveDetected`, `brightness`, `openState`
- Smart Lock: `battery`, `lockState`, `doorState`, `calibrate`
- Bot: `power`, `battery`, `deviceMode`
- Hub 2: `temperature`, `humidity`, `lightLevel`
- Plug Mini JP: `power`, `voltage`, `weight`, `electricityOfDay`, `electricCurrent`

Observed limitations:

- Infrared remotes appeared in `infraredRemoteList`, but status requests returned API error `190 wrong deviceId`.
- The browser UI treats infrared remotes as command/scene targets, not status-capable devices.
- No room classification field was observed in device list or status output.
- No automation definitions were observed.
- No API output suggested device registration, automation editing, or room placement editing.

## Direct Device Command Candidate Policy

The app already supports `device_command` buttons. MVP2 generates candidate ON/OFF buttons only for conservative device types:

- `Ceiling Light`
- `Color Bulb`
- `Plug Mini (JP)`
- `Strip Light`

Bots are not included in ON/OFF generation because the common operation is physical press rather than a clear ON/OFF semantic.
Infrared remotes are not included because they are better handled through SwitchBot scenes.

## Notes

- A successful SwitchBot API response does not always prove the physical device changed state.
- Infrared remotes and physical devices may behave differently for status and commands.
- Device command support should be added conservatively per device type.
